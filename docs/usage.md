# Quick Start Guide

This guide walks you through creating your first VeriGen project - an AXI-Lite register file generator.

## Project Structure

A VeriGen project consists of:

```
my_project/
├── my_project.verigen.yaml    # Project manifest
├── schema.yaml                # Data structure definition
├── ui/
│   └── ui_spec.yaml          # GUI layout (optional)
├── templates/
│   └── rtl/
│       └── module.sv.j2      # Jinja2 templates
└── data/
    └── example.yaml          # Example data files
```

## Step 1: Create the Project Manifest

The manifest file (`.verigen.yaml`) ties everything together:

```yaml
# my_regfile.verigen.yaml
verigen_version: "2.0"

project:
  name: "My Register File"
  version: "1.0.0"
  description: "A simple AXI register file"

schema: "schema.yaml"
ui: "ui/ui_spec.yaml"

templates:
  - source: "templates/rtl/regfile.sv.j2"
    destination: "rtl/{{ module_name }}.sv"
    description: "Main RTL module"

  - source: "templates/sw/regs.h.j2"
    destination: "sw/{{ module_name }}_regs.h"
    description: "C header file"
```

## Step 2: Define Your Schema

The schema defines parameters and data tables:

```yaml
# schema.yaml
version: "2.0"

parameters:
  module_name:
    type: string
    default: "my_regfile"
    pattern: "^[a-zA-Z_][a-zA-Z0-9_]*$"
    description: "Module name"

  data_width:
    type: choice
    options: [32, 64]
    default: 32
    description: "Data bus width"

tables:
  registers:
    display_name: "Registers"
    summary_attribute: name
    nested_table: fields
    attributes:
      - name: name
        type: string
        required: true
        description: "Register name"

      - name: offset
        type: integer
        required: true
        unique: true
        min: 0
        description: "Address offset"

      - name: access
        type: choice
        options: [RW, RO, WO]
        default: RW

  fields:
    display_name: "Fields"
    attributes:
      - name: name
        type: string
        required: true

      - name: bit_offset
        type: integer
        required: true
        min: 0
        max: 31

      - name: bit_width
        type: integer
        required: true
        min: 1
        max: 32
```

## Step 3: Create Templates

Templates use Jinja2 syntax with VeriGen's hardware-focused filters:

```jinja2
{# templates/rtl/regfile.sv.j2 #}
// Auto-generated by VeriGen - Do not edit manually
module {{ module_name }} #(
    parameter DATA_WIDTH = {{ data_width }}
)(
    input  wire                    clk,
    input  wire                    rst_n,
    // AXI-Lite interface
    input  wire [11:0]             s_axi_awaddr,
    input  wire                    s_axi_awvalid,
    output reg                     s_axi_awready,
    input  wire [DATA_WIDTH-1:0]   s_axi_wdata,
    input  wire                    s_axi_wvalid,
    output reg                     s_axi_wready
);

// Register addresses
{% for reg in registers %}
localparam ADDR_{{ reg.name | upper }} = 12'h{{ '%03X' % reg.offset }};
{% endfor %}

// Register storage
{% for reg in registers %}
{% if reg.access != 'RO' %}
reg [DATA_WIDTH-1:0] reg_{{ reg.name | lower }};
{% endif %}
{% endfor %}

// Write logic
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
{% for reg in registers %}
{% if reg.access != 'RO' %}
        reg_{{ reg.name | lower }} <= '0;
{% endif %}
{% endfor %}
    end else if (s_axi_awvalid && s_axi_wvalid) begin
        case (s_axi_awaddr)
{% for reg in registers %}
{% if reg.access == 'RW' or reg.access == 'WO' %}
            ADDR_{{ reg.name | upper }}: reg_{{ reg.name | lower }} <= s_axi_wdata;
{% endif %}
{% endfor %}
        endcase
    end
end

endmodule
```

## Step 4: Generate Code

### Using the CLI

```bash
# Generate with default output directory
verigen generate my_regfile.verigen.yaml

# Specify output directory
verigen generate my_regfile.verigen.yaml -o ./output

# Override parameters
verigen generate my_regfile.verigen.yaml -p module_name=custom_regs -p data_width=64

# Provide data file
verigen generate my_regfile.verigen.yaml -d my_registers.yaml -o ./output
```

### Using the GUI

Launch the graphical interface:

```bash
verigen gui my_regfile.verigen.yaml
```

The GUI provides:

- **Parameter editing** with validation
- **Hierarchical table editor** for registers and fields
- **Live preview** of data structure
- **One-click generation** with output directory selection

## Step 5: Validate Your Data

Validate data files against the schema:

```bash
# Validate a data file
verigen validate schema.yaml --data registers.yaml

# Validate schema itself
verigen validate schema.yaml
```

## Template Filters

VeriGen provides hardware-focused Jinja2 filters:

| Filter | Example | Output |
|--------|---------|--------|
| `hex_format(digits)` | `{{ 255 \| hex_format(4) }}` | `0x00FF` |
| `verilog_hex(width)` | `{{ 255 \| verilog_hex(8) }}` | `8'hFF` |
| `bit_range` | `{{ field \| bit_range }}` | `[7:0]` |
| `mask` | `{{ field \| mask }}` | `255` |
| `log2` | `{{ 256 \| log2 }}` | `8` |
| `clog2` | `{{ 257 \| clog2 }}` | `9` |
| `pow2` | `{{ 8 \| pow2 }}` | `256` |
| `snake_case` | `{{ "CamelCase" \| snake_case }}` | `camel_case` |
| `upper_snake_case` | `{{ "CamelCase" \| upper_snake_case }}` | `CAMEL_CASE` |
| `camel_case` | `{{ "snake_case" \| camel_case }}` | `snakeCase` |
| `pascal_case` | `{{ "snake_case" \| pascal_case }}` | `SnakeCase` |

## Accessing Nested Data

In templates, access nested tables via `.children`:

```jinja2
{% for register in registers %}
Register: {{ register.name }}
  {% for field in register.children %}
  Field: {{ field.name }} [{{ field.bit_offset + field.bit_width - 1 }}:{{ field.bit_offset }}]
  {% endfor %}
{% endfor %}
```

## Custom Validation Rules

Add validation rules to your schema:

```yaml
tables:
  registers:
    attributes:
      - name: offset
        type: integer
        unique: true  # No duplicate offsets

    validation:
      - rule: "offset % 4 == 0"
        message: "Offset must be 4-byte aligned"
```
